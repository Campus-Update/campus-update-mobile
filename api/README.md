# API spec

`openapi-v1.json` is the OpenAPI 3.1 contract for the Campus Update backend
(`Campus-Update/campus-update-api`). Dart models and the API client are generated
from it — do not hand-write them, and do not edit this file.

There is no deployed backend yet, so the spec cannot be fetched from a URL. To
refresh it, run the API locally and export it:

```bash
git clone https://github.com/Campus-Update/campus-update-api
cd campus-update-api
git switch develop          # main is empty, the code lives on develop
createdb campus_update
dotnet restore
dotnet tool restore

export ConnectionStrings__Postgres="Host=localhost;Port=5432;Database=campus_update;Username=$USER"
export Jwt__Key="local-development-only-key-1234567890abcdefghij"

dotnet ef database update \
  --project src/CampusUpdate.Infrastructure \
  --startup-project src/CampusUpdate.Api

dotnet run --project src/CampusUpdate.Api --launch-profile http
```

Then, from this repo:

```bash
curl http://localhost:5124/openapi/v1.json -o api/openapi-v1.json
```

Swagger UI is at <http://localhost:5124/swagger> while the API is running.
Both it and the spec endpoint are development-only.

## Known gaps (15 Sep 2026)

Do not generate the client from this spec yet:

- **Enums are wrong.** `UserRole`, `ContentType`, `ContentStatus`, `UrgencyLevel` and
  `SourceType` are declared `type: integer` with no values, but the API serialises them
  as strings (`"Student"`, `"Urgent"`). Generating now yields `int` fields and every
  call fails to deserialise. Reported to backend.
- **Only `200` is documented** on every operation, so there are no typed error responses.
- **No `securitySchemes`**, so the generated client will not know about Bearer auth.
  Our Dio interceptor handles the token regardless.
